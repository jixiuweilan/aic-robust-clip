## 发出任务前的准备

1. 明确实际姓名与 A/B 的对应关系；两台机器在验收前更新各自独立的 4060 仓库，使用负责人通知中指定的同一提交（须包含本任务说明）。工具初版提交为 `9bf95755f4085d591275b070017444406d9c41f8`，不能将它误作本轮最新交接版本。若统一换成更新提交，须在新版本上重新生成本轮配置及准入证据。
2. 两人都复制 [统一来源配置模板](../configs/templates/4060-source.json) 到各自新的私有任务目录，文件名可用 `source.json`。**只填写九个路径字段**，替换所有 `/REPLACE/` 为本机绝对路径，其他字段保持一致。其中 `train_cache`、`dev_cache` 是兼容字段：本轮 B03 已有 HEAD3 时不读取这两个缓存，可保留历史路径，即使目录不存在，不必传输、创建或重建。其余资产路径需实际核验。模板不能直接执行；也不要用它覆盖旧配置。
3. 核对 `manifest`、`split`、`class_map`、`head/head.json`、`head/head.pt` 的 SHA-256；两台内容须相同。权重 revision 保持模板值。路径可以不同，冻结文件不可编辑。缺失共同 HEAD3 应反馈安排传输，不能自行重新训练。
4. `AIC_SOURCE` 指向填好的 `source.json`；`AIC_MEMBER` 分别为 `A`、`B`；`AIC_TASK` 使用各自从未存在的新目录。按操作手册设置离线变量、GPU、ZIP 映射；确认映射指向本地 Linux 文件系统中的实际 ZIP。
5. 检查期间不切换 Git 提交、不更新环境、不改配置；两台依赖版本保持一致。若必须变更，停止并按新版本重新验收。旧 B03 回传可作历史参考，不能代替本轮准入。

模板中的 `limits` 是保留的有界启动配置字段，不能把它当作正式训练的停止条件。正式实验必须通过 `rtx4060 run` 启动，由该入口落实第三轮暂停。

仅在尚未开始本轮验收、且工作区没有未保存修改的独立 4060 仓库中更新：

```bash
git status --short --branch
git pull --ff-only origin main
git rev-parse HEAD
```

有本地修改、分支不符或无法快进时先反馈，不执行 reset/clean、不覆盖文件。回传完整提交号供负责人核对；两台一致后固定该版本。运行中的 T4 不执行这些命令，本轮验收及训练开始后也不随 main 自动更新。
