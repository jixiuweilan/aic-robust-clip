## 1. 为什么调整主线

用户反馈占位榜分为 **58**，前百超过 70，80 分选手不少、90 分有 5 位。
这是用户观察，未取得平台成绩导出；只读访问官网链接的
[本赛题排行榜](https://reg.aicomp.cn/special/phb/detail?id=4832828643476639839&rwId=4829238709759119407&stbh=4829238709759119431)
时，浏览工具只返回浏览器不支持。因此不能声称独立核验了排名、赛段或对手方案。
没有证据说明别人用了什么方法，更不能据此承诺某条路线能到 80/90。

已核验的项目证据支持调整研究投入：

- [十轮对照](t4-epoch10-results-20260919.md)：N03/P 的 best dev macro
  65.4686%、micro 65.4847%，相对 N00/CE 的 macro 只增 0.0767 个百分点，
  配对预测净多对 8 张。N02/W 当前设置没有胜出。
- [高学习率三轮](t4-lr-high-epoch3-20260920.md)：+0.8767 个百分点是本机
  同轮、单种子、带噪 dev 的早期差值，不是榜分增益，也不代表该方法的提升上限。
- 当前训练是 224 输入、视觉 Q/V rank-4 LoRA、线性分类头、ONLINE10；
  每轮 82,586 个 train 样本。占位使用筛选节点，尚未走最终完整训练数据重训。
  “扩大适配能力可能有收益”是待验证假设，不是已经证明 rank 4 欠拟合。
- 当前宏平均与 micro 只差约 0.016 个百分点，不能解释内部 65.5 与榜上 58 的
  约 7.5 分差距。噪声、分布差异、推理实现等仍是待排查解释。

**决策建议：暂停把学习率/W/P 小范围搜索作为主投入，优先研究
“可靠监督筛选 → 更充分的视觉适配”。** 保留已有基线作为历史锚点。
此次不改旧晋级记录，不把未达门槛的节点重新标为通过。

## 3. 研究结论：方法应改变什么

### 3.1 先判断监督可靠性，再释放视觉适配能力

TURN 和 DeFT 都支持分阶段思路：噪声强时先保护预训练表示，得到更可靠的监督后
再增强任务适配。二者不能证明我们一定涨分，但比“直接增大学习率/全量解冻”有更明确
的因果假设。现有 N01 在线 GCE 的失败，也不能否定冻结特征上 GCE 训练筛选头这一不同用法。

建议先做 **TURN 风格的数字标签分支**。筛选头是新的研究资产，不覆盖旧 HEAD3。
第二阶段采用原 OpenAI ViT-B/32 的视觉参数，明确区分部分解冻和全视觉微调。
未经过独立启动与显存验收，不能假设 8 GB 4060 可以沿用旧 microbatch。

论文 TURN 将各类选中样本数压到最小类数量；500 类时若一类选中为零，可能使全局
训练集归零。移植前必须检查逐类覆盖、GMM 退化和样本量，不能悄悄补选低可靠样本。
如采用保留类间样本量差异的策略，应登记为项目变体，与原方法区别记录。

### 3.2 数字类别 ID 仍可做视觉去噪

FINE 提供不依赖类别名称的结构信号。建议把它与分类损失筛选作为**分别可检验的对照**，
先不把 GMM、近邻、原型、伪标签和对比损失全部堆在同一个新模型中。
类内多模态、背景相似和困难正确样本都可能使视觉筛选出错；筛选概率不能称为真实噪声率。

后续如增加折外分类头或近邻一致性，其训练、拟合与近邻库均只来自 train 分区；
按冻结重复组划分折，避免重复图泄漏。禁止使用 dev/confirm/test 建原型、拟合阈值
或进入无标签损失。冻结官方 CLIP 特征可以缓存复用，但更新过的视觉特征不能冒充冻结缓存。

### 3.3 不可靠样本不应一律强制改成预测类别

先以筛选后训练作为可解释参照，再考察 train 内的不确定样本一致性学习或保守软修正。
模型高置信错误可能自我强化，类别外图像也未必存在正确的 500 类答案。
因此“全部换成 argmax 伪标签”不是默认方案。若采用 EMA 教师，教师来自同一学生轨迹，
只用于 train 监督，最终导出一个模型，不对多个 checkpoint 的预测作融合。
这一方案是项目待验证改造，不冒称等价复现 DivideMix 或 CLIPCleaner 的原结果。

### 3.4 更长训练和更高分辨率是条件分支

SNSCL 作者配置的 warmup 可达 13 轮，不能拿当前三轮观察协议直接淘汰整个方法。
按方法阶段设置观察点，记录已生效更新数、样本访问量、全流程耗时和类别覆盖；
算力成本用于排查工程低效，不设绝对超时淘汰门槛。

增强、分辨率和完整数据重训保留为后续变量。提高输入分辨率必须保留 ViT-B/32
权重与 patch 结构，并审查位置编码插值、预处理、训练/推理一致性；不能换成 B/16。
先在 dev 做独立单因素比较，不与第一轮去噪机制一并改变，也不启用多裁剪投票。
20/30 轮如有依据，应从初始化登记完整新调度，不能把已衰减完的 ONLINE10 硬续成 LONG30。

## 4. 实施前必须回答的两个问题

1. **当前赛段与官方资产是否齐全？** 查阅日期为 2026-09-20，官方通知涉及初赛截止
   和复赛。下一次开跑必须明确属于哪个赛段、有无官方语义类名/独立验证数据。
   只有数字标签时按视觉路线设计；没有类名不能手工补标签。若进入下一赛段，数据、
   初始化、缓存和统计重新隔离，不沿用上一赛段已训练权重。详见[官方复核](../../references/official/20260920-source-review.md)。
2. **提交推理流程能否复现同一 checkpoint 的 dev 预测？** 在训练机器上，复用
   已锁定权重、类别映射、EXIF/RGB 处理、裁剪归一化和数值精度，在 dev 比对逐图
   预测与旧训练验证结果。当前 `predict_dataset()` 只接收 test/inference；未来应
   提供显式 dev 回放检查入口，不能把 dev 伪装成 test 绕过契约。此项尚未实现/执行。
   如存在系统性不一致，先修复并重新验证；一致只能排除这类实现差异，不能说明
   剩余差距一定来自噪声，也不能用重新读取 test 去解释或选择模型。

## 5. 建议的最小研究顺序（不是开跑指令）

| 顺序 | 问题与对照 | 完成后作何决定 |
|---|---|---|
| D0 | 核对当前赛段资产；旧锁模 dev 回放；逐类错误集中度和现有预测分歧 | 排除推理契约问题，确认可用监督形式 |
| R0 | TURN 风格新筛选头；记录逐类损失分布、选中覆盖及筛选稳定性 | 判断该选择器是否退化；无干净标签时不宣称去噪精确率 |
| R1 | 同一新头/适配配置/计划下，全 train CE 对照 vs 筛选后 CE | 隔离筛选贡献；旧 N00 只作历史锚点 |
| R2 | 固定可靠性机制，比较原 Q/V LoRA 与部分或全视觉适配 | 检验原适配能力是否限制收益；先做启动验收 |
| R3 | 获支持的主线分别加视觉结构筛选，或 SNSCL 风格表示学习 | 每次一个机制，有效才考虑组合 |
| R4 | 锁定方法后做稳定性、预算/分辨率敏感性，再按叶子门槛最终重训 | 仅锁定且通过门槛的单模型才进入下一次提交准备 |

R0–R3 尚无可执行配置或已测收益。实现前需冻结主变量、初始化方式、筛选阈值的选择范围、
正式调度、观测点和回退策略，再分配机器。三台机器可以在后续承担配对分支，
但不能把不同机器、不同头初始化和不同工程配置的差异算成纯方法收益。
新源码需新准入，旧 T4 目录不能直接 pull 更新。

评估继续遵循[验证协议](validation.md)：带噪 dev 排名只作暂定判断，报告 macro、micro、
配对错对变化和逐类覆盖；不得把人工筛出的“干净验证集”或模型同意的 dev 子集当作真值。
若主办方提供可用的独立干净验证集，按其使用规则预先登记选择口径。
研究阶段不访问 confirm，不追加占位提交，不以榜分反馈反复选择分支。
